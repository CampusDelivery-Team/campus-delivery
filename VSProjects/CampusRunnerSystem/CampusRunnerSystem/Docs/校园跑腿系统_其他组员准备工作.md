# 其他组员开发前准备工作说明

## 一、说明

本文件用于指导其他组员在克隆项目后完成本地开发环境准备。

本项目是基于 **ASP.NET Core MVC + Oracle 数据库** 的数据库课程设计项目。不同角色成员需要准备的环境略有区别。

---

## 二、所有组员都需要准备的内容

### 1. 安装 Visual Studio 2022

安装 Visual Studio 2022 Community 即可。

安装时必须勾选：

```text
ASP.NET 和 Web 开发
```

这个工作负载用于运行 ASP.NET Core MVC 项目。

---

### 2. 安装 .NET 8 SDK

安装完成后，在命令行检查：

```cmd
dotnet --version
```

如果能看到 `8.x.x` 或更高版本，说明 .NET 环境正常。

---

### 3. 安装 Git 或 GitHub Desktop

建议初学者安装 GitHub Desktop。

需要掌握：

1. Clone 仓库；
2. 切换分支；
3. 提交 Commit；
4. Push 到远程；
5. Pull 最新代码；
6. 创建 Pull Request。

---

### 4. 克隆项目仓库

建议克隆到简单路径，例如：

```text
D:\delivery-backend
```

不要放在中文路径或过深路径中，避免后续工具识别出错。

---

### 5. 打开项目

用 Visual Studio 打开项目中的 `.sln` 文件。

如果没有 `.sln`，也可以打开：

```text
VSProjects/CampusRunnerSystem/CampusRunnerSystem/CampusRunnerSystem.csproj
```

具体以仓库实际结构为准。

---

## 三、后端成员需要额外准备的内容

后端成员需要连接数据库并调试 SQL，因此建议本机安装 Oracle 和 SQL Developer。

### 1. 安装 Oracle 数据库

可以选择：

1. Oracle 19c；
2. Oracle Database XE。

只要版本为 Oracle 18c 或更高即可。

---

### 2. 安装 SQL Developer

SQL Developer 用于：

1. 创建项目用户；
2. 执行建表 SQL；
3. 执行测试数据 SQL；
4. 查询和调试数据库数据。

---

### 3. 创建项目用户 campus

使用 SYS 或 SYSTEM 用户连接到 Oracle 后，执行：

```sql
CREATE USER campus IDENTIFIED BY Campus123456
DEFAULT TABLESPACE USERS
TEMPORARY TABLESPACE TEMP
QUOTA UNLIMITED ON USERS;

GRANT CREATE SESSION TO campus;
GRANT CREATE TABLE TO campus;
GRANT CREATE VIEW TO campus;
GRANT CREATE SEQUENCE TO campus;
GRANT CREATE TRIGGER TO campus;
GRANT CREATE PROCEDURE TO campus;
```

如果使用 PDB，例如 `orclpdb`，需要确认已经连接到 PDB 后再执行。

---

### 4. 执行 24 表建表脚本

在 `campus` 用户下执行：

```text
Database/campus_runner_oracle_schema_cn.sql
```

执行完成后检查：

```sql
SELECT COUNT(*) FROM user_tables;
```

正常结果应为：

```text
24
```

## 四、前端成员是否必须安装 Oracle？

前端成员如果只做页面布局、按钮、表单和样式，短期内可以不安装 Oracle。

但是如果需要完整运行项目、登录系统、查看数据库数据，则也需要安装 Oracle 或连接到某个可用数据库。

建议前端成员至少完成：

1. 安装 Visual Studio；
2. 能成功运行项目；
3. 能打开登录页面；
4. 能看到公共 Layout；
5. 能进入自己负责的页面；
6. 后续联调时再配置 Oracle。

---

## 五、appsettings.json 配置说明

项目通过 `appsettings.json` 连接 Oracle 数据库。

示例配置：

```json
{
  "ConnectionStrings": {
    "OracleConnection": "User Id=campus;Password=Campus123456;Data Source=localhost:1521/orclpdb;"
  }
}
```

不同成员本机 Oracle 服务名可能不同，需要根据自己的环境修改：

| 情况 | Data Source 示例 |
|---|---|
| Oracle 19c PDB | `localhost:1521/orclpdb` |
| Oracle XE | `localhost:1521/XEPDB1` |
| 其他服务名 | `localhost:1521/自己的服务名` |

注意：

1. 连接名必须仍然叫 `OracleConnection`；
2. 不要改成其他名字；
3. 不要把数据库连接写死到 Controller 或 Repository 里。

## 六、克隆项目后的运行步骤

### 1. 拉取代码

```cmd
git clone 仓库地址
```

进入项目目录：

```cmd
cd D:\delivery-backend\VSProjects\CampusRunnerSystem\CampusRunnerSystem
```

### 2. 还原 NuGet 包

```cmd
dotnet restore
```

### 3. 编译项目

```cmd
dotnet build
```

如果显示：

```text
生成成功
0 个错误
```

说明项目编译正常。

### 4. 运行项目

```cmd
dotnet run
```

或直接在 Visual Studio 中点击运行。

### 5. 登录测试

默认账号：

```text
用户名：admin
密码：123456
角色：管理员
```

登录成功后应进入管理员首页。

### 6. 数据库连接测试

进入：

```text
节点管理
```

如果能看到节点数据，说明项目已成功连接 Oracle。

## 七、各类成员开发前需要确认的事

### 前端成员确认

1. 项目能打开；
2. 项目能运行；
3. 自己负责的页面能访问；
4. 不随意修改后端数据库逻辑；
5. 不随意修改公共 Layout；
6. 页面字段要和后端 ViewModel 对齐；
7. 页面文字尽量使用中文。

### 后端成员确认

1. Oracle 能连接；
2. 24 张表已创建；
3. 测试数据已插入；
4. 项目能登录；
5. 自己负责模块对应表结构已看懂；
6. 不随意修改公共连接类；
7. 不直接在 Controller 写 SQL；
8. 所有状态值使用中文枚举。

### 总集成确认

1. 项目能整体运行；
2. main 或 dev 分支能正常编译；
3. 合并前检查冲突；
4. 合并后检查登录和基础页面；
5. 保持 README 和 Docs 更新；
6. 维护统一项目结构。

## 九、中文枚举注意事项

本项目数据库使用中文枚举版。

### 正确写法

```text
管理员
普通用户
跑腿员
正常
禁用
启用
关闭
是
否
已创建
已支付
待接单
已接单
已完成
```

### 错误写法

```text
ADMIN
USER
RUNNER
NORMAL
DISABLED
ENABLED
Y
N
CREATED
PAID
WAITING
FINISHED
```

如果写错英文枚举，可能导致：

1. 数据库 CHECK 约束失败；
2. 插入数据报错；
3. 页面状态判断失败；
4. 权限识别失败。

### 1. 不要直接改 main 分支

```text

feature/backend-task
```

建议使用清晰中文，例如：

```text

修复节点管理删除提示
```

```cmd

```

确认无错误后再提交。

## 十一、常见问题

### 1. 项目运行后数据库连接失败

检查：

1. Oracle 服务是否启动；
2. 服务名是否正确；
3. `appsettings.json` 连接字符串是否正确；
4. `campus` 用户是否存在；
5. 24 张表是否已创建。

### 2. 登录失败

检查：

1. `users` 表中是否有 `admin`；
2. 密码是否是 `123456`；
3. `account_status` 是否是 `正常`；
4. `user_role` 是否是 `管理员`。

### 3. 页面能打开但没有数据

检查对应表是否有数据，例如：

```sql
SELECT * FROM nodes;
SELECT * FROM service_types;
```

### 4. 插入数据时报 CHECK 约束错误

大概率是中文枚举写错，例如写了 `NORMAL` 而不是 `正常`。

### 5. Git 合并冲突

不要自己乱删代码，先联系总集成一起处理。

## 十三、总结

其他组员克隆仓库后，并不是直接就能完整运行项目。

至少需要：

1. Visual Studio 2022；
2. .NET 8；
3. Git 或 GitHub Desktop；
4. 如果要连接数据库，还需要 Oracle 和 SQL Developer；
5. 执行建表 SQL；
6. 执行测试数据 SQL；
7. 修改 `appsettings.json`；
8. 再运行项目。

前端成员可以先不安装 Oracle，但后端成员建议必须安装并配置好数据库。
