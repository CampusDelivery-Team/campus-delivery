# 校园中转分发与跑腿服务管理系统——新版10人详细分工方案

## 一、分工调整背景

本项目为数据库课程设计项目，系统名称为 **校园中转分发与跑腿服务管理系统**。  
项目采用 **ASP.NET Core MVC + Oracle 19c + C# + Bootstrap** 技术路线，数据库使用 **24张表中文枚举版**。

当前总集成负责人已经完成了项目基础框架和管理员基础资料模块，包括：

1. ASP.NET Core MVC 项目基础框架；
2. Oracle 数据库连接；
3. `campus` 用户和 24 张表中文枚举版适配；
4. 登录与角色权限控制；
5. 公共 Layout、顶部栏、侧边栏；
6. 管理员首页；
7. `nodes` 节点管理；
8. `service_types` 服务类型管理；
9. `service_node_rules` 服务节点规则绑定；
10. 上述模块均已通过页面操作和 SQL Developer 查询验证。

分工重点转向 **任务发布、接单状态流转、支付退款、评价投诉、结算审计报表、前端页面完善和联调测试**。

---

## 二、总体分工原则

本项目共 10 人，采用：

```text
3名前端 + 5名核心后端 + 1名测试联调协助 + 1名总集成负责人
```

调整后的原则如下：

1. 总集成负责人已经完成公共框架和管理员基础资料模块，后续主要负责合并、联调和项目稳定性；
2. 前端成员分别负责普通用户端、跑腿员端、管理员端页面；
3. 后端成员按业务模块划分，不再按单表划分；
4. 测试联调协助成员负责测试数据、功能验收、Bug 记录和演示材料整理；
5. 每位成员都需要参与 C# 项目开发或项目联调；
6. 每位成员都要完成自己负责模块的 PPT 内容，并在答辩时讲解自己负责的部分；
7. 所有代码必须遵守现有项目结构，不允许重新创建项目；
8. 所有枚举值必须使用中文，不允许使用英文状态值。

| runners.work_status | 空闲、忙碌、离线 |


4. 发布私人任务；
5. 查询任务列表；

10. 任务取消前置判断；
11. 任务价格保存；
12. 任务初始状态设置。

### 关键业务逻辑

1. 所有任务必须先写入 `tasks` 主单表；
2. 外卖任务再写入 `food_delivery_details`；
3. 快递任务再写入 `express_pickup_details`；
4. 私人任务再写入 `private_task_details`；
5. `tasks.publisher_user_id` 是发布用户；
6. `tasks.node_id` 是交接节点；
7. `tasks.service_type_id + node_id` 必须存在于 `service_node_rules`；
8. 任务创建时要检查服务类型和节点是否合法；
9. 任务状态初始可设为“已创建”；

### 特别注意

不要写错字段名：

| 正确字段 | 错误写法 |
|---|---|
| publisher_user_id | user_id |
| node_id | support_node_id |
| private_task_details | private_item_details |

三类明细表都是联合主键：

```text
task_id + detail_no
```

### 中文枚举要求

| 字段 | 可用值 |
|---|---|
| tasks.urgent_flag | 是、否 |
| tasks.task_status | 已创建、已支付、待接单、已接单、已取件、配送中、待签收、已完成、已取消、退款中 |

8. 支付成功后可推动任务进入后续状态。

### 中文枚举要求

| 字段 | 可用值 |
|---|---|
| payments.pay_method | 微信、支付宝、现金 |
| payments.pay_status | 未支付、已支付、支付失败、已退款 |
| complaints / refunds 状态 | 按 SQL 文件中文枚举为准 |

## 八、开发规范

### 1. 分层结构

所有后端代码尽量遵循：

```text
Controller -> Service -> Repository -> OracleDbHelper -> Oracle
```

说明：

- Controller：负责接收请求和返回页面；
- Service：负责业务逻辑判断；
- Repository：负责 SQL 和数据库访问；
- OracleDbHelper：负责公共数据库连接；
- ViewModel：负责页面与后端之间的数据传递；
- View：负责页面展示。

### 2. 不允许的行为

1. 不允许在 Controller 中直接拼 SQL；
2. 不允许在 View 页面中访问数据库；
3. 不允许随意修改 `OracleDbHelper`；
4. 不允许随意修改 `Program.cs`；
5. 不允许随意修改 `appsettings.json` 中连接名 `OracleConnection`；
6. 不允许改动 24 表建表 SQL；
7. 不允许将中文枚举改回英文枚举；
8. 不允许直接向 `main` 分支推送未测试代码。

### 3. 中文枚举要求

所有业务代码中必须使用中文枚举：

| 类型 | 正确值 |
|---|---|
| 用户角色 | 普通用户、跑腿员、管理员 |
| 账号状态 | 正常、禁用 |
| 是否标志 | 是、否 |
| 审核状态 | 待审核、已通过、已拒绝 |
| 工作状态 | 空闲、忙碌、离线 |
| 节点状态 | 正常、关闭 |
| 服务类型状态 | 启用、禁用 |
| 任务状态 | 已创建、已支付、待接单、已接单、已取件、配送中、待签收、已完成、已取消、退款中 |
| 接派类型 | 自主接单、管理员派单、重新派单 |
| 支付方式 | 微信、支付宝、现金 |
| 支付状态 | 未支付、已支付、支付失败、已退款 |

禁止使用：

```text
USER
RUNNER
ADMIN
NORMAL
DISABLED
CREATED
PAID
WAITING
Y
N
```
