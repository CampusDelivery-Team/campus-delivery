## 第 2 页 · 项目背景与需求分析

- 痛点：校园内快递代取、外卖分发、私人跑腿需求分散，缺乏统一管理

- 核心业务闭环：**发布任务 → 派单/抢单 → 配送送达 → 确认收货 → 支付 → 评价/投诉 → （退款）→ 结算 → 审计**

## 第 3 页 · 系统功能总览（对应"工作量"评分点）

- 功能结构图：按模块列出 **20+ 功能点**（16 个控制器、84 个动作端点）
  - 账户：注册/登录/资料/账号状态管理
  - 地址：地址 CRUD、默认地址唯一约束
  - 任务：发布（餐饮/快递/私人三类）、列表、详情、取消、任务大厅、接单、送达、收货确认
  - 支付：下单支付、支付状态查询
  - 退款：申请、管理员审批
  - 评价：发表（星级+信誉分联动）、修改、删除、我的评价、管理员全量列表
  - 投诉：提交、管理员处理
  - 结算：候选计算、生成、确认、打款
  - 审计：支付/退款/状态日志三类审计登记与核查
  - 报表：运营汇总报表
  - 基础数据：节点、服务类型、节点-服务规则管理
  - 运维：数据库状态诊断页（管理员）
- 明确标注：**其中 15+ 个功能点含实质业务逻辑**（事务、状态机、规则校验），见第 6–7 页

## 第 4 页 · 总体设计 · MVC 五层架构（对应"编码规范性"）

- 架构图：View（cshtml）→ Controller → Service（业务逻辑）→ Repository（SQL）→ Oracle
- 要点：
  - 每层均有接口（`Services/Interfaces`、`Repositories/Interfaces`），DI 注入
  - Controller 不直接访问数据库，按钮/页面事件与 SQL 完全隔离
  - 事务由 `IRepositoryTransactionManager` 统一管理
- 可引用 docs/mvc-five-layer-spec.md、layered-architecture.md

## 第 5 页 · 数据库设计（对应"3NF / 命名 / 主外键"评分点）

- ER 图（24 张表核心部分：users / runners / tasks / 三类任务明细 / assign_records / payments / refunds / reviews / complaints / settlements）
- 论证要点（用实测数据）：
  - **24 张表**（要求 ≥12），**每张表都有主键**（24 个 PK）
  - **31 个外键、141 个检查约束、7 个唯一约束**
  - 命名规范：表名单数 snake_case，约束前缀 `PK_/FK_/UK_/CK_`
  - 3NF 论证：属性原子性、无部分依赖（联合主键表如 assign_records 说明）、无传递依赖（如任务类型拆分为三类明细表而非宽表冗余列）
- 完整性设计亮点：`reviews.task_id` 唯一约束（一任务一评价）+ `(record_id, task_id)` 复合外键绑定真实接派记录

## 第 6 页 · 核心业务逻辑 ① 任务全生命周期

- 状态机图：WAITING → ASSIGNED → DELIVERING → FINISHED →（PAID）/ CANCELLED
- 规则举例：只有已完成且已支付、无在途退款的任务才能评价；取消仅限待接单状态且仅发布人
- 并发控制：`FOR UPDATE` 行锁 + 乐观校验，防止重复接单/重复评价

## 第 7 页 · 核心业务逻辑 ② 资金与信誉

- 支付 → 退款 → 结算的账务链路（settlements 只纳入已支付、已完成、无争议记录）
- 信誉分联动：5★+2 / 4★+1 / 3★+0 / 2★-1 / 1★-2，下限 0 分；修改/删除评价时差额回滚
- 事务一致性：评价入库与信誉分更新同事务，失败整体回滚（讲一个代码例子）

## 附：预测提问与应答要点（Q&A 预案）

| 预测问题 | 应答要点 |
| --- | --- |
| 如何证明满足 3NF？ | 举反例对比：三类任务明细若合并进 tasks 会产生大量可空列与冗余；拆表后无非主属性传递依赖 |
| 并发下两人同时接同一单怎么办？ | `FOR UPDATE` 行锁 + 状态前置校验 + 唯一约束兜底 |
| 数据一致性怎么保证？ | 多表写入均在显式事务中，失败回滚；举例评价+信誉分 |
| 为什么有的 SQL 带 APPUSER. 前缀有的不带？ | 共享库按账号授权，非属主账号通过**同义词**访问业务表；带前缀写法不依赖同义词更稳 |
| 密码怎么存？ | PBKDF2（Identity 哈希）加盐，非明文；有旧格式迁移工具 |
| 连接信息如何保密？ | 配置文件不入库（.gitignore），服务器用环境变量注入 |
| 工作量如何体现？ | 24 表、84 端点、39 测试、14 份文档、验收证据目录 |
