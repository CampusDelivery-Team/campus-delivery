## 演示流程（按顺序）

### ① 开场与架构（约 1.5 分钟 · 建议组员1 讲）

1. 打开首页 `/`：指出导航按访客/用户/跑腿员/管理员四种身份动态展示。
2. 讲解五层结构（对应 PPT 第 6 页）：Controller → Service → Repository → Oracle，强调"按钮事件不直连数据库"，可当场打开一个 Controller 文件展示只调 Service。
3. 打开 `/Database/Status`：显示 Oracle 19c 共享库连接正常，顺带报出 **24 张表、31 个外键、30 个 CHECK 约束**（对应 PPT 第 7 页数据库设计）。

### ② 用户侧：注册 → 发布任务（约 2 分钟 · 建议组员5 讲）

1. `/Auth/Register` 现场注册一个新账号（体现密码哈希存储，可提一句：库里存的是 Identity PBKDF2 哈希，不是明文）。
2. `/Address` 新增一条地址并设为默认——指出数据库有函数唯一索引保证"每用户至多一条默认地址"。
3. `/Task/Create` 发布一条外卖分发任务：选服务类型、节点、地址，填明细——指出停用的服务类型和关闭的节点不会出现在下拉里。
4. 发一条 SQL 证据（可选）：`tasks` 状态 WAITING、`food_delivery_details` 有且仅有一条明细、无支付无接派记录。

### ③ 跑腿员侧：抢单与配送流转（约 2.5 分钟 · 建议组员6 讲）

1. 无痕窗口以跑腿员登录，进 `/Task/Hall` 任务大厅，点抢单。
2. 强调并发控制：抢单在同一事务内先锁任务行和跑腿员行（`FOR UPDATE`），两名跑腿员同时抢也只有一人成功——对应 52 项自动化测试里的并发抢单用例。
3. 依次操作取货 → 配送中 → 送达，展示状态机顺序流转（PICKED_UP → DELIVERING → WAIT_CONFIRM）。
4. 讲点业务规则：跑腿员不能接自己发布的任务；已接单任务管理员可重派，旧接派记录保留（REASSIGN）。

### ④ 收货支付与售后（约 2.5 分钟 · 建议组员7 讲）

1. 发布者窗口 `/Task/Receipt` 确认收货 → `/Payment/Status` 现金支付确认。
2. 展示幂等：重复提交确认收货不会重复生成支付记录。
3. 退款流：对另一条已支付任务 `/Refund/Create` 申请退款 → 管理员窗口 `/Refund/AdminIndex` 审核通过 → 支付状态变 REFUNDED。
4. 讲防绕行规则（2026-08 修复）：已结算的支付不能再发起普通退款（对应 git 提交"禁止已结算订单发起普通退款"）。

### ⑤ 评价、投诉与信誉（约 1.5 分钟 · 建议组员8 讲）

1. 发布者对已完成任务打 5 星评价——指出分数与信誉分联动（5/4/3/2/1 分对应 +2/+1/0/-1/-2），且与评价同事务写入，跑腿员信誉分 100 → 102。
2. 同一任务再评一次被拒（一单一评，数据库 UNIQUE 约束兜底）。
3. 投诉：提交投诉 → 管理员受理、填写处理结果办结。

### ⑥ 管理员侧：结算、审计、报表（约 2 分钟 · 建议组员9 讲）

1. `/Settlement` 为跑腿员生成结算单：展示金额拆分（订单总额 − 平台费 = 净收入），强调只有已支付、已完成、无活动退款的记录才进结算。
2. `/Audit` 审计一笔支付——审计日志与明细同事务写入。
3. `/Report` 统计面板 + 生成订单/支付/投诉三类报表并导出 CSV。

### ⑦ 测试与质量收尾（约 1.5 分钟 · 组员10 讲）

1. 报数：**52/52 自动化测试通过、Release 构建 0 警告 0 错误、24 张表、47/47 POST 防伪令牌、14 处行锁、五层边界零违规**。
2. Bug 闭环举例：云端 404（BUG-001）、评价页 ORA-00933（BUG-003）、迁移未落库（BUG-005）均已完成"登记 → 分配 → 修复 → 回归 → 关闭"闭环，证据在 `docs/test-evidence/manual/`。
3. 指出测试分层：自动化测试守住状态机/事务/并发规则，共享 Oracle 写入型 E2E 证明真实数据库闭环，模块负责人手工测试覆盖各自用例。
