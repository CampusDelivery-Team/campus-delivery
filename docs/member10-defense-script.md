# 组员10 答辩讲稿：测试过程讲解

> 场景：答辩 PPT 第 11 页（testing）测试专题，约 3 分钟讲稿 + 问答准备。
> 定位：我是本项目的测试负责人，负责统一制定测试用例和 Bug 清单、收集各组截图与 SQL 证据、亲自执行跨模块端到端测试、组织彩排。

## 一、开场（约 20 秒）

各位老师好，我是组员10，负责本项目的测试工作。我从三个方面汇报：测试体系怎么设计、怎么执行、发现了什么问题以及怎么闭环。

## 二、测试体系设计（约 50 秒）

我们没有把测试写成简单的增删改查罗列，而是分了三层：

**第一层是 52 项自动化测试**。它们守住的是最容易出错的业务规则——并发抢单、任务状态机的非法跳转、确认收货的幂等、支付和评价的事务一致性、结算状态机、报表生成导出。这些用例用仓储接口测试替身隔离 Oracle，每次提交代码都能跑一遍，是稳定回归的底线。

**第二层是共享 Oracle 写入型端到端验收**。自动化测试隔离了数据库，所以我们另外用真实应用页面加真实 Oracle 做了一轮写入型验收：从注册、发单、抢单、配送到收货、支付、评价、结算全链路，数据都是通过 MVC 页面和防伪令牌产生的，数据库只用来只读复核结果。我们还做了真实双会话并发验证——两个人同时抢一单，最终只有一条有效接派记录。

**第三层是分工执行模块手工测试**。我编写了 `test-plan.md`，给组员 1 到 9 每人一套带前置条件、步骤、预期结果的用例，共约 80 条，各负责人测自己的模块，提交截图或 SQL 证据，我负责抽查和汇总。

## 三、执行结果（约 40 秒）

目前的结果是：

- Release 构建 0 警告 0 错误，自动化测试 **52 项全部通过**，比 8 月 22 日的 39 项又增加了 13 项，覆盖了后续修复的回归场景；
- 静态质量门禁 5 类全部通过：24 张表、47 个 POST 接口全部有防伪令牌、14 处仓储行锁、五层边界零违规、连接字符串全部外置配置；
- 模块测试方面，账户权限、基础资料、评价投诉三个模块已完成并提交证据，用例结论均为通过，其余模块证据在持续收集中；
- 所有证据按"日期 + 用例编号"归档在 `docs/test-evidence/` 目录，欢迎老师抽查。

## 四、Bug 闭环（约 50 秒）

测试发现的问题全部走统一流程：**任何人发现 Bug → 我登记 → 分配给模块负责人 → 修复 → 我回归测试 → 通过后关闭**，登记在 Bug 清单里，编号不回收。

举三个例子：

1. 第一轮截图验收时发现云端还是旧版本、新版路由全部 404——定为严重级，重新部署后我回归确认所有新路由正常，已关闭；
2. 管理员评价查询页报数据库错误，定位是评价分页 SQL 拼接问题——迁移落库并修复后我回归通过，修复前的报错截图也保留在证据目录里，作为对比；
3. 还发现过数据库完整性迁移没有落库，评价外键、默认地址唯一索引都不存在——补执行迁移后只读验证全部生效。

目前台账上 6 个 Bug：4 个已关闭，1 个界面文案问题已修复待补回归截图，1 个是我在复核证据 SQL 时发现的脚本与表结构脱节的次要问题，已分配待处理。没有未登记的已知缺陷。

## 附：预设问答（Q&A）

**Q：并发抢单怎么保证只有一个人成功？**
A：抢单在同一个数据库事务里，先对任务行和跑腿员行加 `FOR UPDATE` 行锁，再更新任务、跑腿员、接派记录和状态日志。谁先拿到锁谁成功，另一个会话等待后看到任务已不是 WAITING 就被拒绝。这个场景既有自动化测试，也做过真实双会话并发复核。

**Q：52 项自动化测试为什么不多写一些 CRUD 测试凑数？**
A：我们的原则是测试高价值业务规则而不是凑数量。简单的增删改查由模块手工测试覆盖，自动化留给状态机、事务、并发、幂等这些一旦出问题就是脏数据的规则。

**Q：密码是明文存的吗？**
A：不是。全部用 ASP.NET Core Identity 的 PBKDF2 带盐哈希，组员2 的数据库测试里有 SQL 证据，密码列全是哈希值。历史上做过一次从明文到哈希的迁移，是 005 号迁移脚本。

**Q：怎么保证测试数据不污染共享库？**
A：端到端验收全部用专用标识（E2E、X2 前缀）隔离，测试账号和数据保留在库里供老师复核，没有清理或修改团队既有业务记录，也没有在仓库里提交任何密码或连接凭据。

**Q：越权访问测过吗？**
A：测过三层：普通用户和跑腿员访问管理员页面会拒绝，这是 Controller 上的角色授权；用户 B 用用户 A 的地址 ID 发单会被服务端校验拒绝；被评价任务不属于当前用户也会拒绝——身份都取自登录态而不是页面参数。组员3 的账户权限模块测试里都有截图和 SQL 证据。

**Q：如果演示现场系统起不来怎么办？**
A：所有关键流程都有带日期的截图和 SQL 证据归档在 `docs/test-evidence/manual/`，可以直接讲解证据材料，不影响结论。
