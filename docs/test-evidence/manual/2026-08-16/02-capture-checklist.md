# 核心流程补拍清单

## 1. 拍摄前准备

- 新版应用运行在可访问地址，页面提交号为 `2917db9` 或更高。
- 使用隔离 Oracle 测试库，已执行结构脚本和 `002` 至 `006` 迁移。
- 准备 U1、U2、R1、R2、R3、A1 六个测试账号。
- R1、R2 使用两个独立浏览器会话，避免 Cookie 混用。
- 浏览器缩放保持 100%，窗口宽度建议不低于 1280 像素。
- 截图前清除与本次用例无关的通知，不显示密码和连接字符串。

## 2. 推荐拍摄顺序

1. 拍摄 `ENV-04` 数据库连接正常和 `ENV-05` 自动化测试通过。
2. U1 登录，完成地址、资格申请和三类任务发布。
3. A1 完成资格审核、配置维护、派单/重派。
4. R1、R2 完成普通抢单与并发抢单。
5. 当前跑腿员完成配送状态流转。
6. U1 完成确认收货、支付、评价、投诉和退款申请。
7. A1 完成投诉、退款、结算、审计和报表。
8. 最后拍摄越权、重复提交和非法状态等负向场景。

## 3. 单张截图判定规则

截图必须同时包含以下三类信息中的至少两类：

- 页面标题或模块导航，证明当前功能位置；
- 任务编号、状态、金额等关键业务结果；
- 成功/失败提示，证明操作实际结果。

页面截图不能单独证明数据库事务正确。FLOW-02、04、06 至 20 必须运行 `sql/verification.sql` 中的对应查询，并将 SQL Developer 结果另存为同编号 `.txt` 或截图。

## 4. 截图后处理

1. 仅裁掉桌面、聊天窗口等无关区域，不裁掉功能标题和状态。
2. 对手机号、身份证号、真实姓名等个人数据打码。
3. 不修改状态文字、金额、时间和成功提示。
4. 在 `01-screenshot-index.md` 中把状态改成 `PASS` 或 `FAIL`。
5. 如为 `FAIL`，在 `04-bug-record.md` 新增一行并填写对应截图。
