# 审计与报表功能入门说明

本文档用于辅助执行组员9后半部分测试用例，重点对应：

- `TC-SETTLE-06`：三类审计。
- `TC-SETTLE-07`：统计面板。
- `TC-SETTLE-08`：报表生成与导出。
- `TC-SETTLE-09`：删除报表不动审计。
- `TC-SETTLE-10`：跑腿员查看本人结算。

这里不替代每个测试用例文档，而是解释审计和报表是什么、为什么数据库项目要做这些功能、当前项目里具体怎么实现，以及测试时 SQL 应该怎么验证。

## 1. 审计是什么

审计可以理解为“对关键业务数据做核查并留下记录”。

在数据库课程设计里，审计通常用来回答这些问题：

- 某笔支付是否正常？
- 某笔退款是否合理？
- 某条任务状态流转日志是否符合业务流程？
- 管理员什么时候检查过这些数据？
- 检查结果是正常还是异常？
- 如果异常，异常说明是什么？

注意：当前项目里的审计不是 Oracle 数据库自带的审计，也不是自动触发器记录所有 SQL 操作。它是一个业务审计功能：管理员在网页上选择业务对象，然后手动创建审计记录。

## 2. 当前项目的审计设计

当前系统把审计分成“主表”和“明细关联表”。

### 2.1 审计主表

`APPUSER.audit_logs` 保存每次审计动作本身。

核心字段：

- `audit_id`：审计记录编号。
- `audit_object`：审计对象类型，目前支持 `PAYMENT`、`REFUND`、`LOG`。
- `audit_result`：审计结果，目前支持 `PASS`、`ABNORMAL`。
- `audited_at`：审计时间。
- `exception_note`：异常说明，可为空。

### 2.2 审计明细关联表

不同审计对象对应不同的关联表：

- `APPUSER.audit_payment_checks`：保存某次审计关联了哪些 `payment_id`。
- `APPUSER.audit_refund_checks`：保存某次审计关联了哪些 `refund_id`。
- `APPUSER.audit_status_log_checks`：保存某次审计关联了哪些 `log_id`。

这种设计的好处是：

- `audit_logs` 统一保存所有审计记录。
- 具体审计了哪些业务数据，由不同关联表表达。
- 一次审计可以选择多条目标记录。
- 后续报表可以引用审计记录作为“审计依据”。

## 3. 审计功能在 C# 里怎么实现

审计功能的调用链大致是：

```text
浏览器页面
  -> AuditController
  -> AuditService
  -> AuditRepository
  -> Oracle 数据库
```

### 3.1 Controller 层

`AuditController` 负责接收网页请求。

主要入口：

- `GET /Audit`：显示最近审计记录和三类可审计对象数量。
- `GET /Audit/Create?auditObject=PAYMENT`：进入支付审计创建页。
- `GET /Audit/Create?auditObject=REFUND`：进入退款审计创建页。
- `GET /Audit/Create?auditObject=LOG`：进入状态日志审计创建页。
- `POST /Audit/Create`：提交审计结果。

Controller 不直接写 SQL，它只负责把请求转给 Service，并把结果展示到页面。

### 3.2 Service 层

`AuditService` 负责业务规则。

它主要做三件事：

1. 根据审计类型加载候选对象。
2. 校验审计类型必须是 `PAYMENT`、`REFUND`、`LOG` 之一。
3. 创建审计时开启事务，先写 `audit_logs`，再写对应明细关联表。

创建审计时的关键逻辑可以概括为：

```text
开始事务
  插入 audit_logs，得到 audit_id
  遍历管理员选择的 targetIds
    根据 auditObject 插入对应关联表
提交事务
如果中途失败
  回滚事务
```

这就是测试用例里说的“同事务写入”。

### 3.3 Repository 层

`AuditRepository` 负责具体 SQL。

它会从不同业务表读取候选审计对象：

- 支付审计候选来自 `payments`、`assign_records`、`tasks`。
- 退款审计候选来自 `refunds`。
- 状态日志审计候选来自 `task_status_logs`、`assign_records`、`tasks`。

创建审计时，它会先插入：

```sql
INSERT INTO APPUSER.audit_logs (audit_object, audit_result, audited_at, exception_note)
VALUES (:auditObject, :auditResult, SYSDATE, :exceptionNote)
RETURNING audit_id INTO :auditId;
```

然后根据审计类型插入不同关联表。例如支付审计：

```sql
INSERT INTO APPUSER.audit_payment_checks (audit_id, payment_id)
VALUES (:auditId, :targetId);
```

## 4. 审计测试时 SQL 要看什么

测试审计功能时，不是只看页面提示“保存成功”，还要证明数据库里主表和明细表都写对了。

### 4.1 查最近审计主记录

```sql
SELECT audit_id, audit_object, audit_result, audited_at, exception_note
FROM APPUSER.audit_logs
ORDER BY audit_id DESC
FETCH FIRST 20 ROWS ONLY;
```

如果刚刚做了支付审计，应看到一条 `audit_object = 'PAYMENT'` 的记录。

### 4.2 查支付审计明细

```sql
SELECT
    a.audit_id,
    a.audit_object,
    a.audit_result,
    apc.payment_id,
    p.pay_status,
    p.pay_amount
FROM APPUSER.audit_logs a
JOIN APPUSER.audit_payment_checks apc
    ON apc.audit_id = a.audit_id
JOIN APPUSER.payments p
    ON p.payment_id = apc.payment_id
WHERE a.audit_id = :audit_id;
```

这条 SQL 的作用是证明：这条审计记录确实绑定到了某笔支付。

### 4.3 查退款审计明细

```sql
SELECT
    a.audit_id,
    a.audit_object,
    a.audit_result,
    arc.refund_id,
    rf.payment_id,
    rf.process_status,
    rf.refund_amount
FROM APPUSER.audit_logs a
JOIN APPUSER.audit_refund_checks arc
    ON arc.audit_id = a.audit_id
JOIN APPUSER.refunds rf
    ON rf.refund_id = arc.refund_id
WHERE a.audit_id = :audit_id;
```

这条 SQL 的作用是证明：这条审计记录确实绑定到了某笔退款。

### 4.4 查状态日志审计明细

```sql
SELECT
    a.audit_id,
    a.audit_object,
    a.audit_result,
    aslc.log_id,
    tsl.record_id,
    tsl.status_before,
    tsl.status_after,
    tsl.operated_at
FROM APPUSER.audit_logs a
JOIN APPUSER.audit_status_log_checks aslc
    ON aslc.audit_id = a.audit_id
JOIN APPUSER.task_status_logs tsl
    ON tsl.log_id = aslc.log_id
WHERE a.audit_id = :audit_id;
```

这条 SQL 的作用是证明：这条审计记录确实绑定到了某条任务状态变化日志。

## 5. 报表是什么

报表可以理解为“把业务数据按某个口径汇总后展示出来”。

审计关注的是“某条或某批数据是否被核查过”；报表关注的是“某段时间内整体业务情况怎么样”。

例如：

- 这个月发布了多少任务？
- 完成了多少任务？
- 支付了多少钱？
- 有多少退款？
- 有多少投诉？
- 哪些节点任务量最多？
- 哪些跑腿员完成单量高？

在这个项目里，报表功能主要给管理员使用，用来查看平台运行情况和导出统计结果。

## 6. 当前项目的报表设计

报表功能也分成几层：

```text
浏览器页面
  -> ReportController
  -> ReportService
  -> ReportRepository
  -> Oracle 数据库
```

### 6.1 报表首页

`GET /Report` 显示实时统计面板。

这些指标不是从 `reports` 表读出来的，而是打开页面时直接从业务表实时统计：

- `tasks`：任务总数、已完成任务。
- `payments`：已支付金额。
- `settlements`：已结算净收入。
- `refunds`：退款记录数。
- `complaints`：未处理投诉数。
- `nodes` + `tasks`：节点业务量。
- `runners` + `assign_records` + `tasks` + `payments` + `settlements`：跑腿员绩效。

所以 `TC-SETTLE-07` 的重点是：页面数字要和 SQL 手算结果一致。

### 6.2 报表主表

`APPUSER.reports` 保存报表生成记录。

核心字段：

- `report_id`：报表编号。
- `report_type`：报表类型，支持 `ORDER`、`PAYMENT`、`COMPLAINT`。
- `stat_period`：统计周期，例如 `2026-08`。
- `generated_at`：生成时间。
- `report_status`：报表状态，生成后为 `GENERATED`，导出后为 `EXPORTED`。

注意：`reports` 表本身不保存所有业务明细。它保存的是“生成过一张什么类型、什么月份、什么状态的报表”。

### 6.3 报表审计依据表

`APPUSER.report_audit_items` 保存报表和审计记录的关联。

字段：

- `report_id`：报表编号。
- `audit_id`：审计编号。

它表达的是：这张报表引用了哪些审计记录作为依据。

当前实现中：

- `ORDER` 报表关联同月份的 `LOG` 审计。
- `PAYMENT` 报表关联同月份的 `PAYMENT` 和 `REFUND` 审计。
- `COMPLAINT` 报表主要展示投诉业务明细和指标，当前不强制关联审计记录。

## 7. 报表功能在 C# 里怎么实现

### 7.1 Controller 层

`ReportController` 主要入口：

- `GET /Report`：显示统计面板和最近报表。
- `POST /Report/Generate`：生成指定类型、指定月份的报表。
- `GET /Report/Details/{id}`：查看报表详情。
- `POST /Report/Export/{id}`：导出 CSV。

当前没有删除报表的入口，所以 `TC-SETTLE-09` 需要记录为“阻塞 / 需确认”，除非后续补充删除功能。

### 7.2 Service 层

`ReportService` 做业务组织：

- `GetDashboardAsync`：读取实时统计指标、节点排行、跑腿员绩效、最近报表。
- `GenerateAsync`：校验报表类型和月份，插入 `reports`，插入适用的 `report_audit_items`。
- `GetDetailsAsync`：读取报表记录，再按报表类型和月份查询业务明细。
- `ExportAsync`：生成 CSV 文件，并把报表状态更新为 `EXPORTED`。

生成报表的大致流程：

```text
校验 reportType 是否为 ORDER / PAYMENT / COMPLAINT
校验 statPeriod 是否为 yyyy-MM
根据月份计算 periodStart 和 periodEnd
查询该周期业务明细，用于计算指标
开始事务
  插入 reports，状态 GENERATED
  查询适用的 audit_id
  插入 report_audit_items
提交事务
```

导出报表的大致流程：

```text
查询 reports
根据 report_type 和 stat_period 查询业务明细
查询 report_audit_items 关联的审计依据
组装 CSV 文本
添加 UTF-8 BOM，避免中文乱码
更新 reports.report_status = 'EXPORTED'
返回文件给浏览器下载
```

### 7.3 Repository 层

`ReportRepository` 负责 SQL。

它会提供这些数据：

- 统计面板指标。
- 节点业务量排行。
- 跑腿员绩效排行。
- 最近报表。
- 某类报表的业务明细。
- 某张报表关联的审计依据。
- 插入报表主表。
- 插入报表审计关联。
- 更新报表状态。

## 8. 三类报表的统计口径

### 8.1 ORDER 报表

订单报表按任务创建时间统计：

```sql
t.created_at >= :periodStart
AND t.created_at < :periodEnd
```

业务明细来自：

- `APPUSER.tasks`
- `APPUSER.service_types`
- `APPUSER.nodes`

它适合回答：某个月平台发布了哪些任务，任务状态和金额是什么。

### 8.2 PAYMENT 报表

支付报表按任务完成时间统计；如果没有完成时间，则回退到任务创建时间：

```sql
NVL(t.completed_at, t.created_at) >= :periodStart
AND NVL(t.completed_at, t.created_at) < :periodEnd
```

业务明细来自：

- `APPUSER.payments`
- `APPUSER.assign_records`
- `APPUSER.tasks`
- `APPUSER.refunds`

它适合回答：某个月有哪些支付记录、支付状态如何、是否有关联退款。

### 8.3 COMPLAINT 报表

投诉报表按关联任务创建时间统计：

```sql
t.created_at >= :periodStart
AND t.created_at < :periodEnd
```

业务明细来自：

- `APPUSER.complaints`
- `APPUSER.assign_records`
- `APPUSER.tasks`

它适合回答：某个月有哪些投诉，投诉状态和原因是什么。

## 9. 报表测试时 SQL 要看什么

### 9.1 查最近报表

```sql
SELECT report_id, report_type, stat_period, generated_at, report_status
FROM APPUSER.reports
ORDER BY report_id DESC;
```

生成报表后应看到新记录，状态为 `GENERATED`。导出后再查，应变为 `EXPORTED`。

### 9.2 查报表审计依据

```sql
SELECT
    rai.report_id,
    rai.audit_id,
    a.audit_object,
    a.audit_result,
    a.audited_at
FROM APPUSER.report_audit_items rai
JOIN APPUSER.audit_logs a
    ON a.audit_id = rai.audit_id
WHERE rai.report_id = :report_id
ORDER BY rai.audit_id;
```

这条 SQL 用来证明报表关联了哪些审计记录。

如果某张 `COMPLAINT` 报表没有审计依据，不一定代表失败，因为当前实现主要为 `ORDER` 和 `PAYMENT` 报表关联审计依据。

### 9.3 手算统计面板

```sql
SELECT COUNT(*) AS task_count
FROM APPUSER.tasks;
```

```sql
SELECT COUNT(*) AS finished_task_count
FROM APPUSER.tasks
WHERE task_status = 'FINISHED';
```

```sql
SELECT NVL(SUM(pay_amount), 0) AS paid_amount
FROM APPUSER.payments
WHERE pay_status = 'PAID';
```

```sql
SELECT NVL(SUM(net_income), 0) AS settled_net_income
FROM APPUSER.settlements
WHERE settlement_status IN ('WAITING', 'DONE');
```

```sql
SELECT COUNT(*) AS refund_count
FROM APPUSER.refunds;
```

```sql
SELECT COUNT(*) AS pending_complaint_count
FROM APPUSER.complaints
WHERE process_status IN ('SUBMITTED', 'PROCESSING');
```

这些 SQL 对应 `/Report` 首页的核心指标。

## 11. 一句话总结

审计是“管理员对关键记录做检查并留下证据”；报表是“系统按时间和类型汇总业务数据并可导出”。当前项目里，审计数据落在 `audit_logs` 和三张审计明细表，报表数据落在 `reports` 和 `report_audit_items`，页面展示的数据还会实时从任务、支付、退款、投诉、结算等业务表中查询计算。
